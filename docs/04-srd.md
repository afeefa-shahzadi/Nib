# Mycelium SRD

## Document Purpose
This Style Requirements Document defines the visual, interaction, editorial, and brand style system for Mycelium. It covers interface aesthetics, typography, layout, theming, motion, information density, and front-end taste guidelines for the platform prototype and future production product.

## Style Direction
Mycelium should feel like a hybrid of premium editorial software and intelligent product infrastructure. The design language should communicate seriousness, calm depth, and creative sophistication rather than generic startup energy.

The visual personality should avoid common AI-generated aesthetics such as glowing purple gradients, decorative blob backgrounds, overly rounded template layouts, and feature-card sameness. Instead, it should lean toward restrained editorial surfaces, thoughtful type contrast, selective accent color, and purposeful interface hierarchy.

## Design Principles
- Editorial before decorative.
- Calm surfaces, precise accents.
- Dense capability, simple first impression.
- Strong information hierarchy.
- Left-aligned reading-first layouts by default.
- Motion that clarifies transitions rather than adding spectacle.

## Brand Character
### Tone attributes
- Thoughtful.
- Advanced.
- Quietly futuristic.
- Trustworthy.
- Knowledge-rich.
- Creator-centric.

### Avoided attributes
- Loud.
- Hyper-playful.
- Crypto-like.
- Neon-gaming.
- Corporate-generic.
- Social-media-chaotic.

## Color System
The palette should remain neutral-led with one primary accent and limited secondary accents.

### Core colors
- Background: warm dark charcoal in dark mode and warm paper beige in light mode.
- Surface: slightly elevated neutral layers.
- Text: high-contrast soft white in dark mode and rich charcoal in light mode.
- Primary accent: teal to blue-green family.
- Secondary support accents: muted blue or muted violet only when semantically useful.

### Usage rules
- Accent color should signal action and selected state.
- Content surfaces should stay mostly neutral.
- Multiple accent hues should not compete in a single viewport unless representing distinct information states.
- Monetization cards may use subtle accent tinting, not full-saturation blocks.

## Typography
### Font pairing
- Display font: refined serif with character and authority.
- Body font: modern sans-serif with high readability.

### Hierarchy rules
- Display typography reserved for hero moments, major page titles, and premium editorial emphasis.
- Body typography used for functional UI, cards, controls, and long-form content.
- Paragraph text should remain comfortably readable and never feel oversized in application views.
- Small labels should remain legible and restrained.

### Tone outcome
The combined typography should suggest that the product understands both writing and systems.

## Layout System
### General layout
- Use a clean app shell for studio views.
- Use narrower reading widths for article-like content.
- Use wider, modular dashboard widths for analytics and graph views.
- Preserve strong spacing rhythm with clear section grouping.

### Grid approach
- Two-column dashboard sections are preferred for studio workspaces.
- Three-column grids should be used carefully and only where content naturally parallels.
- Full-width moments should be reserved for graph, editor canvas, or hero framing.

## Component Styles
### Navigation
- Sidebar navigation should feel quiet, clear, and editorial rather than enterprise-heavy.
- Active state should be obvious but not loud.

### Cards
- Cards should use subtle elevation, neutral borders, and consistent radius.
- Avoid colored left borders or loud panel treatments.

### Buttons
- Primary buttons use the accent color.
- Secondary buttons use neutral surfaces and soft borders.
- Tertiary actions should feel lightweight and contextual.

### Pills and chips
- Chips can be used for block types, modes, metadata, or states.
- Chips should look informative, not playful.

## Motion
- Motion should be brief, smooth, and purposeful.
- Theme switches, mode changes, panel reveals, and graph transitions should feel polished.
- Reduced motion support should be mandatory.
- Heavy parallax, floating ornament motion, and decorative chaos should be avoided.

## Reading Experience Style
- Standard mode should prioritize focus and typographic clarity.
- Expert mode should feel denser but still organized.
- Teach mode may use stronger scaffolding, callouts, and checkpoints.
- Debate mode should visually separate argument, response, and moderation states.

## Front-end Quality Bar
The interface should look credible alongside modern advanced editorial and interactive product experiences, where navigation, content structure, and interaction quality matter as much as raw visuals.[web:11][web:14][web:18]

## Accessibility Style Rules
- Contrast should meet WCAG AA minimums.
- Focus states must be visible and elegant.
- Touch targets must remain mobile-friendly.
- Typography must remain legible across themes and responsive states.
- Meaning should not depend only on color.
